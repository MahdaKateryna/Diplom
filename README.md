1. ЗАГАЛЬНИЙ ОПИС
================================================================================

Graph Viewer — застосунок для візуалізації та аналізу графів на основі
бібліотек NetworkX та Matplotlib (інтерфейс Tkinter).

Програма підтримує роботу з двома окремими незорієнтованими графами (G1 та G2),
що можуть з'єднуватися дугами-зв'язками (Links), утворюючи об'єднаний граф
(Combined). Кожна дуга має два числових атрибути — відстань (distance) та
вартість (cost), — що використовуються як ваги в алгоритмах.

Підтримувані алгоритми:
  - Найкоротший шлях (НШ) — повний перебір усіх простих шляхів між кожною
    парою «джерело → стік» з вибором оптимального за обраним критерієм.
  - Форд-Фалкерсон (ФФ) — обчислення максимального потоку між кожною
    парою «джерело → стік» методом найширшого шляху.

Обидва алгоритми доступні у двох режимах:
  - Швидкий (Compute fast)           — миттєвий результат із підсвічуванням.
  - Покроковий (Compute step-by-step) — детальна анімація кожного кроку.

3. ІНТЕРФЕЙС ПРОГРАМИ
================================================================================

ЛІВА ПАНЕЛЬ — керування (вертикально прокручується):
  ┌─ Graph 1 edges ──────────────────────────────────────────┐
  │  Текстове поле для дуг Graph 1 (формат: u,v,d,c)         │
  │  Sources — поле для вершин-джерел G1 (через кому)        │
  │  Sinks   — поле для вершин-стоків G1 (через кому)        │
  │  [Load G1]              [Load G1 from file]              │
  ├─ Graph 2 edges ──────────────────────────────────────────┤
  │  (аналогічно до Graph 1)                                 │
  │  [Load G2]              [Load G2 from file]              │
  ├─ Links (sink G1 → source G2) ────────────────────────────┤
  │  Текстове поле для дуг-зв'язків між G1 та G2             │
  │  [Add Links]            [Links from file]                │
  ├─ Рекурентне керування графами ───────────────────────────┤
  │  [➕ Додати граф з файлу] [➖ Вилучити граф з файлу]     │
  │  [↩ Скасувати останню операцію]                          │
  ├─ Алгоритм ───────────────────────────────────────────────┤
  │  ◉ Найкоротший шлях (НШ)   ○ Форд-Фалкерсон (ФФ)         │
  ├─ Критерій ───────────────────────────────────────────────┤
  │  ◉ distance   ○ cost                                     │
  ├─ Запуск ─────────────────────────────────────────────────┤
  │  [Compute (fast)]   [Compute (step-by-step)]             │
  │  [Порівняти швидкість (НШ vs ФФ)]                        │
  │  [← Назад]  [Вперед →]          Крок: X / Y              │
  └──────────────────────────────────────────────────────────┘
  Інформаційне поле (результати обчислень / опис поточного кроку)

ПРАВА ПАНЕЛЬ — вкладки з інтерактивними графами:
  Graph 1   — візуалізація першого графа (дуги блакитні)
  Graph 2   — візуалізація другого графа (дуги червоні)
  Combined  — об'єднаний граф: G1 + G2 + Links (зелені)

Вузли можна перетягувати мишею на будь-якій вкладці — положення
зберігається між перемальовуваннями.

Кольори вузлів:
  Сірий   — вершина є джерелом або стоком.
  Зелений — поточне активне джерело (у покроковому режимі).
  Світло-сірий — звичайна вершина.

4. ФОРМАТ ВХІДНИХ ДАНИХ
================================================================================

ДУГИ ГРАФА (одна дуга на рядок):
  вершина1, вершина2, відстань, вартість

  Приклад:
    A, B, 5, 10
    B, C, 3, 7
    A, C, 8, 15

  Правила:
  - Імена вершин — довільні рядки без ком (A, B, Node1, СТ-1 тощо).
  - Граф є незорієнтованим: дуга A-B та дуга B-A — одне й те саме.
  - Дублікати дуг в межах одного графа заборонені.
  - Відстань і вартість — числа (цілі або дробові, крапка як розділювач).
  - Порожні рядки та рядки-коментарі (починаються з #) ігноруються.

ДЖЕРЕЛА та СТОКИ — через кому у відповідних полях:
  A, C     ← Sources (поле Sources)
  D, F     ← Sinks   (поле Sinks)

  Важливо: вершини-джерела та вершини-стоки мають бути присутні у графі.

ФОРМАТ ПОВНОГО ФАЙЛУ (підтримується скрізь, де є вибір файлу):
  # Коментар
  edges:              ← необов'язковий заголовок секції
  A,B,5,10
  B,C,3,7
  C,D,4,8
  sources: A          ← необов'язкова секція; кілька вершин через кому
  sinks: D            ← необов'язкова секція
  links: X,A,2,5      ← необов'язкова секція; одна дуга на рядок або після ':'

  Усі секції (edges:, sources:, sinks:, links:) є необов'язковими.
  Порядок секцій — довільний.
  Підтримувані кодування файлів: UTF-8, UTF-8-BOM (utf-8-sig), Windows-1251.

5. ЗАВАНТАЖЕННЯ ГРАФІВ
================================================================================

─── Спосіб 1: Ручне введення ─────────────────────────────────────────────────

  1. Введіть дуги у текстове поле «Graph 1 edges» (формат: u,v,d,c).
  2. Введіть джерела через кому у поле «Sources».
  3. Введіть стоки через кому у поле «Sinks».
  4. Натисніть [Load G1].
  5. Повторіть кроки 1–4 для Graph 2 та натисніть [Load G2].
  6. За потреби введіть зв'язки у поле «Links» та натисніть [Add Links].

─── Спосіб 2: Завантаження з файлу ──────────────────────────────────────────

  1. Натисніть [Load G1 from file] або [Load G2 from file].
  2. Оберіть текстовий файл (.txt або інший).

  Файл може містити лише рядки дуг (u,v,d,c) або повний формат із секціями
  sources:, sinks:, links: (секція links: при завантаженні G1/G2 з файлу
  ігнорується).

  Якщо у файлі присутні секції sources: та/або sinks:, їхні значення
  автоматично підставляються у відповідні поля інтерфейсу — вводити вручну
  не потрібно.

  Приклад файлу з усіма секціями:
    A,B,4,10
    A,C,6,8
    B,D,3,5
    C,D,2,4
    sources: A
    sinks: D

─── Зв'язки між графами (Links) ──────────────────────────────────────────────

  Links з'єднують стоки G1 із джерелами G2, утворюючи наскрізний маршрут
  через об'єднаний граф.

  Вимоги при використанні [Add Links] та [Links from file]:
  - Перша вершина дуги link має бути у списку Sinks G1.
  - Друга вершина — у списку Sources G2.

  Приклад:
    D, E, 1, 2    ← D — стік G1, E — джерело G2

  УВАГА: при додаванні графів через [➕ Додати граф з файлу] перевірка
  links: є суворішою (див. розділ 8).


================================================================================
6. РОБОТА З АЛГОРИТМАМИ
================================================================================

─── Вибір алгоритму ──────────────────────────────────────────────────────────

  ◉ Найкоротший шлях (НШ)
    Знаходить усі прості шляхи між кожною парою (джерело → стік) методом
    Мінті та визначає оптимальний (або кілька рівнооптимальних).
    Одночасно обчислює найкоротший шлях за distance та за cost.

  ◉ Форд-Фалкерсон (ФФ)
    Обчислює максимальний потік від кожного джерела до кожного стоку.
    Алгоритм ітеративно знаходить шляхи з найбільшим вузьким місцем
    (Widest Path), оновлює залишкову мережу і підсумовує потік.

─── Вибір критерію ───────────────────────────────────────────────────────────

  ◉ distance — ваги дуг беруться з першого числового поля (відстань).
  ◉ cost     — ваги дуг беруться з другого числового поля (вартість).

  Для НШ у швидкому режимі обидва критерії обчислюються одночасно
  та підсвічуються різними кольорами.
  У покроковому режимі та у ФФ критерій обирається перед запуском.

─── Швидкий режим: [Compute (fast)] ─────────────────────────────────────────

  Програма миттєво:
  1. Обчислює результат для всіх пар (джерело → стік).
  2. Виводить результат в інформаційне поле.
  3. Підсвічує оптимальні дуги на активній у момент запуску вкладці.

  Кольорове підсвічування — НШ (fast):
    Синій   (жирний)   — найкоротший шлях за distance.
    Червоний(жирний)   — найкоротший шлях за cost.
    Фіолетовий(жирний) — шлях є оптимальним одночасно за distance та cost.

  Кольорове підсвічування — ФФ (fast):
    Темно-зелений      — дуги, задіяні у максимальному потоці.
    Мітки дуг          — змінюються на «залишок/використано».

─── Активна вкладка ─────────────────────────────────────────────────────────

  Алгоритм застосовується до графа тієї вкладки, що відкрита під час запуску:
    Graph 1   → аналізується лише G1 (джерела та стоки G1).
    Graph 2   → аналізується лише G2 (джерела та стоки G2).
    Combined  → аналізується об'єднаний граф (джерела G1 → стоки G2).

7. ПОКРОКОВИЙ РЕЖИМ
================================================================================

  1. Оберіть алгоритм, критерій і потрібну вкладку.
  2. Натисніть [Compute (step-by-step)].
  3. Програма будує повний список кроків і відображає перший.
  4. Навігація між кроками:
       [Вперед →]  — наступний крок.
       [← Назад]   — попередній крок.
  5. Лічильник «Крок: X / Y» показує поточну позицію.
  6. Опис кожного кроку виводиться в інформаційне поле.

  Кольорове підсвічування — НШ (покроковий):
    Зелений   (жирний)  — дуги вже пройденого відрізку поточного шляху.
    Помаранчевий        — дуги, що розглядаються як кандидати.
    Синій     (final)   — підсумковий оптимальний шлях за distance.
    Червоний  (final)   — підсумковий оптимальний шлях за cost.
    Фіолетовий(final)   — шлях оптимальний за обома критеріями.

  Кольорове підсвічування — ФФ (покроковий):
    Помаранчевий        — шлях, що зараз розглядається.
    Зелений             — шлях, яким пропускається черговий потік.
    Темно-зелений(final)— підсумкові дуги максимального потоку.
    Мітки дуг           — «залишок/використано» оновлюються на кожному кроці.

  Покроковий режим зручний для навчання та презентацій алгоритмів.
  Запуск нового покрокового обчислення скидає попередній список кроків.


================================================================================
8. РЕКУРЕНТНЕ КЕРУВАННЯ ГРАФАМИ (ДОДАТИ / ВИЛУЧИТИ)
================================================================================

Операції дозволяють нарощувати або скорочувати граф, завантажуючи
зміни з файлів, без повного перезавантаження.
Перед кожною операцією автоматично зберігається знімок стану (для Undo).

─── Додати граф з файлу [➕] ─────────────────────────────────────────────────

  Поведінка залежить від поточного стану:

  СТАН А — G1 порожній:
    Файл завантажується як Graph 1.
    Граф у файлі повинен бути зв'язним.

  СТАН Б — G1 існує, G2 порожній:
    Файл завантажується як Graph 2.
    Секція links: у файлі задає з'єднання між G1 і новим G2.

    Вимоги до файлу:
      - Новий граф повинен бути зв'язним.
      - Новий граф не повинен мати спільних вершин або дуг із G1.
      - Кожна дуга links: має з'єднувати одну вершину G1 з однією
        вершиною нового графа (не дві з одного боку).
      - Дуга links: не повинна вже існувати в G1.

  СТАН В — G1 і G2 обидва існують:
    Поточний об'єднаний граф (G1 + G2 + поточні Links) стає новим G1.
    Граф із файлу стає новим G2.
    Links між ними — лише ті, що вказані у файлі (секція links:).
    Позиції вузлів скидаються для перекомпонування.

  Помилки, що блокують додавання:
    - Новий граф незв'язний.
    - Новий граф має спільні вершини з існуючим.
    - Нові дуги вже наявні в поточному графі.
    - links: вказують невірні вершини (обидві з одного боку або відсутні).
    - Дуга links: вже існує в поточному графі.

─── Вилучити граф з файлу [➖] ──────────────────────────────────────────────

  Файл містить дуги та/або links, які потрібно видалити з поточного графа.

  Правила:
    - Усі вказані дуги повинні існувати в поточному графі; якщо хоч одна
      відсутня — вилучення скасовується.
    - Після вилучення граф (G1 і G2 окремо розглядаються через Combined)
      має залишатися зв'язним. Якщо вилучення розіб'є граф на компоненти —
      операція відхиляється з поясненням.
    - Ізольовані вершини (без дуг після вилучення) видаляються автоматично
      з попередженням-підтвердженням.
    - Секція links: у файлі задає зв'язки, що також видаляються з Links.
    - Секції sources: та sinks: у файлі вилучають відповідні вершини
      зі списків джерел/стоків G1 і G2.

─── Формат файлу для рекурентних операцій ───────────────────────────────────

  # Файл для додавання нового підграфа з'єднаного з існуючим
  E,F,5,9
  F,G,3,6
  G,H,2,3
  sources: E
  sinks: H
  links: D,E,1,2

  # Файл для вилучення конкретних дуг
  B,D,3,5
  C,D,2,4

  # Файл для вилучення дуг і зв'язків одночасно
  B,D,3,5
  links: D,E,1,2

9. СКАСУВАННЯ ОПЕРАЦІЙ (UNDO)
================================================================================

  Кнопка [↩ Скасувати останню операцію] скасовує останню виконану дію.

  Підтримує скасування для:
    - [Load G1] / [Load G2]
    - [Load G1 from file] / [Load G2 from file]
    - [Add Links] / [Links from file]
    - [➕ Додати граф з файлу]
    - [➖ Вилучити граф з файлу]

  Що відновлюється:
    - Структура та атрибути G1 і G2 (вершини, дуги, ваги).
    - Списки джерел та стоків G1 і G2.
    - Список Links.
    - Вміст текстових полів та полів Sources/Sinks.

  Глибина скасування необмежена — зберігається вся сесія.


================================================================================
10. ПОРІВНЯННЯ ШВИДКОСТІ АЛГОРИТМІВ
================================================================================

  Кнопка [Порівняти швидкість (НШ vs ФФ)] стає активною лише після того,
  як обидва алгоритми виконані через [Compute (fast)] хоча б по одному разу.

  Порядок дій:
    1. Оберіть «Найкоротший шлях» і натисніть [Compute (fast)].
    2. Перемкніться на «Форд-Фалкерсон» і натисніть [Compute (fast)].
    3. Натисніть [Порівняти швидкість (НШ vs ФФ)].

  Результат відображає:
    - Час виконання кожного алгоритму в мілісекундах.
    - Текстову гістограму (рядки з «=»), що унаочнює відносну швидкість.
    - Висновок: який алгоритм швидший і в скільки разів.

  Вимірюється лише час обчислення (без часу відмальовування графа).
  Результати оновлюються щоразу при новому запуску Compute (fast).

  «ModuleNotFoundError: No module named 'networkx' / 'matplotlib'»
    → Встановіть необхідні бібліотеки командою:
      pip install -r requirements.txt

  «Граф порожній»
    → Завантажте дуги через текстове поле або файл і натисніть Load.

  «Не задані джерела або стоки»
    → Заповніть поля Sources і Sinks перед запуском алгоритму.

  «Bad format: ...»
    → Перевірте формат рядка: рівно 4 поля через кому (u,v,d,c).
      Переконайтеся, що d та c — числа (не текст).

  «Новий граф не є зв'язним»
    → Усі вершини файлу мають бути з'єднані між собою.
      Перевірте, чи не розпадається граф на окремі компоненти.

  «Новий граф має спільні вершини з існуючим»
    → Графи мають бути повністю незалежними за назвами вершин.
      Використовуйте секцію links: для з'єднання, а не спільні вершини.

  «Нові дуги вже наявні в існуючому графі»
    → Дуга з такою парою вершин уже існує. Видаліть дублікат із файлу.

  «З'єднувальна дуга X-Y: обидві вершини належать існуючому графу»
    → Дуга links: повинна з'єднувати один кінець з існуючим графом,
      а інший — з новим. Перевірте назви вершин.

  «Вилучення розіб'є граф на N частини»
    → Операція заблокована. Спробуйте вилучити менше дуг або видалити
      такий набір, після якого решта залишається зв'язною.

  «Нічого не вилучено»
    → Жодна з дуг файлу не знайдена у поточному графі. Перевірте назви
      вершин та числові значення — вони мають точно збігатися.

  «Неможливо додати дугу» (Add Links)
    → Перша вершина links має бути у Sinks G1, друга — у Sources G2.

  «Порівняння недоступне»
    → Запустіть [Compute (fast)] окремо для НШ і для ФФ, потім порівнюйте.

  Файл не читається / UnicodeDecodeError
    → Збережіть файл у кодуванні UTF-8, UTF-8-BOM або Windows-1251.
